# Standalone evidence provider and System handoff

Workflow evidence interface 1 is independent of native Dream Report versions 1/2. Existing validators and historical Markdown reports remain unchanged. `dreaming-evidence` uses only local Workflow standard-library modules and requires no AI System installation. A provider read stays pending; it cannot claim semantic review, current Quality, completed distillation or owner approval.

System consumption must compare current actual provider source fingerprints with its explicitly reviewed binding. Unknown interface/provider versions are rejected; missing current quality evidence remains unknown. Native lifecycle `new/repeated/promoted/rejected/obsolete/unknown` is preserved. No local installation/update/release is implied.

The integration protocol is explicit registry → bounded private chunks → actual existing-agent analysis → local completion → candidate review. Prompt injection in sources stays data. Private/public lesson and each WEP derivative retain their own review gates. Shared outputs consume reviewed projections, never the private chunks or inventory.

Native QA/capture readers may assess current meaning only after all inputs they would read pass the same source guard. Their names or a PASS label do not establish actual Quality. Without a scope-safe input closure, export `unknown` or `stale`, with a limitation; do not run them against arbitrary source-provided paths.

The provider calls the existing native QA/capture readers only on the already guarded, bounded byte inventory. Each declared QA input must have been disclosed by that broker and match its native checksum. Unknown input closure, V3 bindings or historical admission remain unknown rather than following source-provided paths. Exact owning identity and accepted distillation gates remain native.
