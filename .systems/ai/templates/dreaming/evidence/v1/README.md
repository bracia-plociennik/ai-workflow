# Evidence interface v1

The normative executable validator is `.systems/scripts/dreaming_evidence.py`. JSON objects have exactly the required fields; unknown versions and additional authority fields are rejected. `provider-fixture.json` is synthetic, copied by bytes into the consumer contract tests, never permission evidence.

Source references bind owner, root/project, relative path, current bytes, observation time and evidence level. Native lifecycle and native quality remain separate. `promoted` with `unknown` quality is not WEP approval. `complete` requires full enumeration and no pending/unsupported/blocked/missing item. A read alone remains pending. Actual capability fingerprints must be recomputed at the local installed producer and compared with the accepted consumer binding.

The body broker owns validated read/analysis receipt semantics; this pure transport validator rejects missing receipts and evidence from unread or excluded inventory. It does not certify understanding or source truth. No legacy Dream Report reader/schema is changed.
