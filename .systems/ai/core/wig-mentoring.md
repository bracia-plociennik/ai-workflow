# WIG mentoring consumer V1

System owns selected personal priority sources and task-scoped private state under its wig-mentoring.md. This Workflow consumes only the verified System lead's minimal wig-mentoring-project-v1 projection, through .systems/scripts/prepare-wig-mentoring on stdin. It never reads a personal default, check-in, exception reason or private WIG title from the target repository.

Projection is descriptive: contract, authority none, execution_authorized false, task_hash/context_hash, action quiet/clarify/suggest-return and one typed reason code. Reject extra keys/private payloads, unknown versions, permission claims, malformed identities or inconsistent actions without echoing input. A syntactically valid projection is not producer provenance, owner approval or a native mentoring proof; the lead independently verifies current context and ownership. Missing/invalid/unbound System context leaves normal execution gates in place and does not invent a priority.

At new-task, next-task, material scope-change and plan-review request the scoped System lead's assessment. Do not re-evaluate individual commands, ordinary questions, tests or continuation. A reminder is brief and nonblocking; no compulsory justification or automatic detour. Aligned tasks, necessary dependencies, incidents and genuinely urgent commitments can legitimately precede WIG. Once an intervention was shown, System records seen; a conscious owner deviation records exception for that stable task until its actual end. Resume is not a new task. New confirmed goal/material commitment context can trigger re-evaluation. Never infer inactivity, procrastination, WIG completion or owner exception from missing telemetry or a status checkbox.

Owner chooses priorities. Respect deliberate exceptions, rest and personal commitments. Do not invent extra hardening after DoD, mandatory next work, task lifecycle writes, timers, ledger approval, personal memory export, agents or scheduler. Required safety/QA remains binding. Target artifacts stay local; no raw personal data or private projection is written to project logs/evidence. Product fixtures contain synthetic data only. Missing support is unknown, not automatic setup or a second Workflow clone.

Use the stable owning work-unit identity (parent task plus existing Workflow task/slice ID), not a fresh ID per command or the entire multi-month roadmap. Important/backlog metadata is context, not proof of urgency or inactivity. Material context references must remain stable across resume; do not replace them with newly phrased narratives for every step.
