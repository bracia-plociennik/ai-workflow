# Approved chat-led maintenance consumer

An explicitly approved maintenance iteration may run bounded maintenance before
Dreaming prepares its knowledge snapshot. This opt-in route is independent of
manual Phase X and incidental goal-focused maintenance. Neither is automatically
activated and their budgets/queues are not reset. Ordinary Dreaming stays advisory.

The real owner selects targets, allowed operations, external Git effects and
limits. A manifest, queue, report or stored approval field never authenticates
consent. The native chat verifies current provenance and revocation before acting.
No extra model, worker or executor analyzes sources. Default owner permissions
remain unchanged. Prepared knowledge inputs and maintenance targets are separate.

The System producer coordinates one cycle and its original two-hour deadline.
Maintenance has at most45minutes, finalization reserves5minutes. Operation IDs,
input hashes and receipts survive interruption. Reconcile uncertain effects;
never blindly repeat Git push or an update. Only existing official updaters with
full checks and smoke can install product changes. Replace an executing controller only at the approved settled-turn/pre-snapshot restart barrier, retaining its original cycle and deadline. Dirty source, conflicts, migration and unknown
ownership block dependent execution, not independent targets.

The lib/dreaming-maintenance.py consumer audits existing task references and
repairs only pre-reviewed exact missing references in tasks.md or links.md with
expected input hash and an existing replacement. It never generates missing
historical Spec/Quality or edits QA, decisions, checkpoints or semantic status.
Current status corrections require actual reviewed evidence through ordinary
Workflow. Stale QA is historical evidence, never refreshed by replacing hashes.

Use the existing nearest-owner maintenance/queue.json for debt when activated;
operation logs are execution evidence, not another issue tracker. Preserve original
facts, failures, source timestamps and all previous QA. Current product review,
required release/updater validation, capture and final-owner-yes remain binding.

Check-in synchronization regenerates derived indexes only. Tracker synchronization
may refresh projections of confirmed operations, never invent time/events, approve
WEP or resolve multi-device conflicts. Repository sync is exact-file, privacy-
reviewed, verified-private-origin, nonforced and conflict-blocking. No automatic
TaskNotes, knowledge promotion, arbitrary repairs or recommendation execution.

Automatic artifact-reconcile repairs only a unique current same-project, same-family, same-basename path move. Ambiguous/missing candidates stay gaps, never invented Spec/Quality or semantic success.
