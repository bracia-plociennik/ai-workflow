## Skill plan

**Proposed name:** `review-local-cli-safety`

**Trigger:** Use when the user asks to assess a specific local shell or CLI command, command sequence, or script invocation *before it runs*, including its effect on files, git state, credentials, processes, or network access.

| Should trigger | Should not trigger |
| --- | --- |
| “Is `rm -rf build/` safe from this directory?” | “Run the configured unit tests.” |
| “Review this `git clean` command before I use it.” | “Review this application code for security bugs.” |
| “Could this shell pipeline expose secrets or write outside the checkout?” | “Explain what `git status` displays.” |
| “Check the safety of this local migration command.” | “Lint this shell script for style.” |

**Proposed behavior:** Identify the command’s working directory and target scope; account for shell expansion, quoting, pipes, redirection, and substitutions; classify observable reads, writes, deletion, network effects, and uncertainty. Report the specific risk, evidence needed, and a safer command or inspection step where useful. Never treat the skill as execution approval or run a command merely to review it. Defer to repository risk, permission, and phase gates.

**Artifact map for a later authorized build:** A concise `SKILL.md` with trigger, review procedure, authority boundary, output format, and stop conditions; a short `README.md`. Add a reference only if real examples make the entrypoint too long. No script is justified for v1.

**Validation plan:** Review a local, static set of positive and near-miss prompts for trigger precision. Check that reviews catch destructive targets, hidden shell effects, secrets, and external effects without executing commands. Then run the skill validator and applicable AI Workflow checks. A green validator alone would not establish behavioral quality.
