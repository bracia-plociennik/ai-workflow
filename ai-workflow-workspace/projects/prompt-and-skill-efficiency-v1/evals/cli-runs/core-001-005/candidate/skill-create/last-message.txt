## Proposed skill: `local-cli-command-safety`

**Target for a future authorized build:** `.systems/ai/skills/local-cli-command-safety/`. Put the canonical procedure in `SKILL.md` and a short human summary in `README.md`. Add a reference file only if the command-effect checklist makes `SKILL.md` unwieldy. No script is needed for the initial version.

**Candidate trigger description:** “Review a proposed local CLI or shell command before execution for filesystem changes, destructive effects, network access, credential exposure, indirect script behavior, and required AI Workflow permissions. Use for command safety review and safer local alternatives; do not use to authorize or execute commands.”

| Should trigger | Should not trigger |
| --- | --- |
| “Is `git reset --hard` safe here?” | “Run `git reset --hard`.” Execution needs its own authorization and gates. |
| “Review this `find … -delete` command before I run it.” | “Explain how `find` syntax works.” A general tutorial has no proposed action to review. |
| “Can I safely run `npm test` in this checkout?” | “Review this application code for security flaws.” That is code or security review. |
| “Check whether this `curl … \| sh` command has external effects.” | “Approve this production deployment.” That requires the production risk route. |
| “Compare these two local cleanup commands for risk.” | “Create a skill for command safety.” That invokes `skill-creator`, as this planning task does. |

**Review procedure to specify in `SKILL.md`:**

1. Record the exact command, working directory, shell, relevant environment, and intended outcome. Treat missing context as unknown.
2. Inspect the whole command, including substitutions, pipes, redirects, globbing, `sudo`, aliases, and invoked scripts or package tasks. Do not execute the proposed command to find out what it does.
3. Identify possible writes, deletion, network calls, credential access, external effects, and effects outside the checkout. Classify risk under the existing AI Workflow risk model.
4. Report a verdict of **locally reviewable**, **conditional on missing facts**, or **blocked by an existing gate**. State the evidence and uncertainty. Offer a narrower inspection command when one is genuinely safe.
5. Preserve the authority boundary: the skill cannot override `AGENTS.md`, permissions, phase gates, approvals, or the rule against destructive and external actions.

**Evaluation plan:** Manually test positive triggers and near-miss non-triggers, then compare skill-assisted answers with a baseline. Include straightforward inspection (`rg --files`), indirect execution (`npm test`, `make clean`), destructive commands, `curl … | sh`, redirects, and an opaque `python -c` command. Check that answers inspect indirect effects, avoid false assurance, never execute the candidate command, and distinguish review from approval. Keep any future eval output in the authorized project workspace, outside the skill directory.
